Privacy engineering

Clinical document de-identification engine

Realistic clinical documents are what training, demos and software testing need, and real patient data is exactly what they must never contain. This engine swaps identifiers for demo patients you choose and leaves the rest of the document as it was.

StackPython, PyMuPDF, Tesseract and PP-OCR, ONNX Runtime, Pyodide/WebAssembly
Runs onSealed Docker container, a single Windows .exe, or a browser tab
StatusWorking tool; Windows package rebuilt by CI on every change

The problem

Test data that still looks like a chart

Teams that train staff, demo software or test interfaces need documents that look like the real thing: the same layouts, the same lab tables, the same scanned faxes and DICOM headers. Blacking out identifiers ruins them, and hand-editing does not scale. Generic redaction tools also tend to remove too much, so the document stops being useful, or too little, so it is not safe to share.

The brief was strict: change only text that could identify a person, keep every other word, value, image and layout element exactly where it was, and never let a file pass silently.

What was built

One engine, three ways to run it

  • Format coverage: Word, Excel and PowerPoint edited at the XML level, text and scanned PDFs, multi-page TIFF and other images, DICOM (headers, UIDs and burned-in pixel text), Outlook .msg and .eml with attachments, HL7 v2, FHIR, CDA and plain text.
  • Demo data you choose: a seed file or spreadsheet of demo patients, providers and an organization. Each real person maps to the same demo person across the whole batch, values are matched by meaning rather than spelling (a birth date is replaced in every format it appears in), and other dates shift by one offset so timelines stay coherent.
  • Surrogates that blend in: replacement text on scans is drawn in the closest matching font, weight, size, ink colour, blur and grain.
  • Three runtimes: a network-less, read-only Docker container; a single Windows executable; and the same Python engine running entirely inside a browser tab through WebAssembly.
  • Agent access: the engine can run as an MCP tool server, so Microsoft Copilot agents can run batches through it.

Approach

Nothing passes silently

Detect→Seed→Rewrite in place→Re-read output→Leak check→Status
  • Every output is re-read. Text layers, XML parts, DICOM headers and a fresh OCR of rendered pages are searched for every original value found in the batch.
  • Four honest outcomes. Each file ends as processed, needs review, failed the leak check (renamed so it cannot pass as clean), or could not be processed. Reports carry counts and positions, never original values.
  • Rules first, model second. Labelled fields, dictionaries and context rules catch the common layouts; an optional open clinical language model (a BERT model trained for de-identification, run offline through ONNX) adds names in free text. It can only add detections, and it re-checks itself on load and switches off if its answers drift.
  • Optional encrypted crosswalk. When a batch needs a way back to the source, the mapping is sealed with AES-256-GCM under a passphrase-derived key (PBKDF2, 600,000 iterations), refused inside the output folder, and readable by the CSeed desktop app too.
  • Tested on invented data only. The automated suite runs every format on synthetic fixtures, on Linux and Windows in CI, and leak-checks the built Windows executable on a fixture batch.

What it shows

Privacy as an architecture decision

The safest place for patient data is a place it never leaves. This project treats that as a design constraint rather than a policy: no network in the container, nothing written but the output, a browser build whose content security policy forbids outside contact, and verification that trusts the finished file rather than the code that produced it.

It also shows restraint about claims. The documentation is explicit that this is surrogate replacement for test, demo and training data, that it does not certify HIPAA de-identification, and that a human spot-check stays in the loop.

This page describes the tool's design. No real patient data appears on it or in the tool's test suite.
