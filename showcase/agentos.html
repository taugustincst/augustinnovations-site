AgentOS: a personal agent operating system

Agents that read your mail and calendar are only useful if you can trust them with both. AgentOS runs scheduled and on-demand agents on a phone or a server, and every design choice starts from one question: what stops outside text from acting in the owner's name?

StackKotlin (native Android), Node.js kernel, SQLite, Playwright
Runs onAndroid phone, laptop, home server or VPS, as peers of each other
StatusWorking app; signed APK built by GitHub Actions; shared conformance suite

The problem

Useful agents need access, and access needs a boundary

A personal agent layer over email, calendar, files and meetings can draft replies, prepare briefs and keep tasks moving. The same access makes it a target: any email or web page it reads can carry instructions. The goal was an always-on system that is genuinely useful while making that kind of injection structurally unable to act.

What was built

Two kernels, one behaviour

  • A native Android app that runs the whole system on the phone: scheduler, twelve built-in agents, approval gate, memory, task list and console. Only model calls and the owner's connected-service reads leave the device.
  • A desktop kernel in Node.js with the same agents and console, plus browser automation and sandboxed tools; the two can act as peers through a gateway.
  • Provider-neutral models: Claude, Gemini or any OpenAI-compatible endpoint, with automatic failover to a second provider and a daily token spend cap.
  • Operational resilience: checkpoints before every self-modifying action with one-tap rollback, compaction so long jobs can finish, a loop guard for stuck runs, and a watchdog that pauses a failing schedule and says why.

Approach

Taint follows the work

Outside content→Wrapped and tainted→Writes and fetches queue→Owner approves
  • Taint tracking. Anything from outside the boundary arrives wrapped and marks the run. A tainted run's persistent writes, messages and even outbound reads wait for the owner's tap, and the taint carries into any work that run delegates or schedules.
  • Sends always wait. Email and text sends are approval-gated no matter what, and self-modification (building tools, spawning agents, restoring checkpoints) is never eligible for autonomy.
  • Earned, revocable autonomy. An identical, clean, unedited action approved repeatedly can stop asking, but only if the owner turns that on; every action taken alone leaves a receipt, and taking one back revokes the allowance.
  • Secrets sealed and redacted. Keys are encrypted at rest on both platforms and scrubbed from error text and logs before a model or a log collector can see them.
  • One spec, two implementations. A shared conformance suite of test vectors must pass on both the Kotlin and Node kernels, so they cannot drift apart silently; CI adds end-to-end browser tests and behavioural tests against real SQLite.

What it shows

Agent safety as engineering, not a disclaimer

Prompt injection is the central risk of putting AI agents near real data. AgentOS shows a practical, layered response: classify what came from outside, make that classification sticky, put the high-consequence actions behind a person, and document plainly what the design does not defend against. The same thinking carries directly to agents that work near clinical systems.
