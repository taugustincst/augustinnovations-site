CSeed — Product Fact Sheet

AugustInnovations LLC · Current version: 1.0.1 (Windows) Prepared: October 23, 2026

What CSeed does

CSeed de-identifies clinical documents and seeds realistic synthetic data in place of the real identifiers — so clinical documents can be used safely for software testing, demos, training, and workflow development. It runs entirely on the user's own Windows machine: no cloud, no uploads, no data ever leaves the workstation.

Key facts
Platform Windows (single self-contained application)
Input formats DOCX, PDF (including OCR of scanned pages via bundled Tesseract), TXT, CSV, HL7, FHIR
Consistency The same person maps to the same fake identity across every document in a batch — names, dates, MRNs, addresses, and contacts stay internally consistent
Crosswalk The real↔fake mapping is saved only as an AES-256-GCM encrypted file under a per-batch passphrase chosen by the user
Leak check Output is verified against the source identifiers before release; a run that fails its leak check is stamped FAILED and is not shareable
Dates Dates are shifted consistently, preserving intervals and document chronology

Known limitations (stated plainly)

  • Scanned-image PDFs are still being hardened. Documents with a real text layer pass CSeed's leak check cleanly on the current version. Pure scanned-image documents (OCR-only path) are under active remediation: a recent scanned test file still leaked some identifiers on that path and was correctly flagged FAILED by CSeed's own verifier. Treat scanned-image PDFs as not yet supported until a future release notes otherwise.
  • The installer is not code-signed, so Windows SmartScreen shows a warning on first run.
  • Handwriting recognition is limited; low-confidence OCR is flagged for review rather than silently passed.

Validation

Version 1.0.1 passed a 364-test automated suite and a full re-run on a 55-page real-world-format EHR test document with zero leaked identifier kinds. Validation notes are available on request.
